利用条件

商用利用禁止・再配布禁止

利用できる範囲・出典表記

  • 非商用のサービス・ツールでの画面表示および分析に利用できます。
  • 有料サービス、広告収益を伴うサービス、販売促進などの商用目的では利用できません。
  • JSONの転載、ミラー公開、APIなどを介した第三者への再提供は禁止します。加工したデータの再配布も含みます。
  • 利用する画面またはクレジット欄に「難易度データ：CPI:Next」と、CPI:Nextへのリンクを掲載してください。
  • PredやFeatureを加工して表示する場合は、その旨を明記してください。

データの性質・免責

PredとFeatureは独自の推定・分析によるもので、公式の難易度評価ではありません。正確性・完全性・継続提供は保証しません。利用により生じた損害について責任を負いかねます。

データの取得

最新版JSON バージョン一覧JSON

バージョンを確認しています。

対象は現在サイトに掲載しているSP譜面です。ユーザーのクリアランプや個人データは含みません。

JavaScriptでの取得例

const response = await fetch(
  "https://cpi-next.com/data/v1/latest.json",
  { cache: "no-cache" }
);
if (!response.ok) throw new Error("データを取得できませんでした");
const data = await response.json();
console.log(data.dataVersion, data.charts);

取得時のお願い

認証不要の静的ファイルです。APIキーやJSONPは使用しません。ブラウザからは通常のGETで取得してください。変更確認にはバージョン一覧を利用し、全データを取得するのは初回・更新時に限ってください。

データ仕様

UTF-8のJSONです。オブジェクトや配列の並び順に依存せず、IDと項目名で参照してください。

ファイル全体

項目意味
schemaVersionデータ形式の版。現在は数値の 1。
dataVersion内容の版。作成日（JST）と内容のSHA-256先頭12桁。
updatedAtそのデータ版を初めて生成した日時。ISO 8601・UTC。
chartCountchartsに含まれる譜面数。
documentationこの利用案内のURL。
usage商用利用・再配布の可否と、出典表記の必要性。詳しい条件は本ページを参照。
featureDefinitionsFeatureの固定IDと日本語名の対応表。
charts譜面オブジェクトの配列。

譜面ごとの項目

{
  "id": "1",
  "title": "ADAMANT",
  "difficulty": "ANOTHER",
  "level": 11,
  "pred": { "easy": 11.87, "normal": 12.09, "hard": 12.47 },
  "features": [
    { "id": "charge_note", "strength": 1 },
    { "id": "scratch_complex", "strength": 1 }
  ]
}
  • id：既存の譜面ページと共通のchartId。文字列です。別譜面への再利用はしません。
  • title：曲名。
  • difficulty：NORMAL / HYPER / ANOTHER / LEGGENDARIA。
  • level：公式レベル。
  • pred：個人補正を含まないPred。easyはイージー、normalはノマゲ、hardはハード。未算出の場合は null。0や空文字へ置き換えないでください。
  • features：Featureの配列。特徴なしは []。強度は通常が 1、+が 2、++が 3です。

Featureは、同程度のPredの譜面に比べて相対的にその特徴が強いことを示します。

バージョン管理

latest.jsonは最新版です。結果を再現したい場合は、下記の固定版URLを利用し、使用した dataVersionを記録してください。

同じ内容の再生成では、版と日時は変わりません。データが過去と同じ内容へ戻った場合は、既存の同内容の版を再利用します。過去版の中身は書き換えません。

形式の互換性を壊す変更では v2のように提供先を分けます。譜面の追加・削除、Pred・Featureの修正はv1内のデータ更新です。利用側では欠損値と削除されたIDも考慮してください。

バージョン一覧の latestが最新の dataVersionです。各版の urlは一覧JSONからの相対パス、sha256はファイル全体の検証用ハッシュ、contentSha256は日時などを除いた内容の識別用ハッシュです。ハッシュは改ざんを防ぐ署名ではありません。
